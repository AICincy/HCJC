How to read this: the sweep appends one blocked record to the ledger for each cycle in which HCSO’s portal returned blocked or empty responses to the roster-list retrieval, and one recovered record when a healthy sweep closes the denial period. Detail-phase failures are recorded separately: one detail_page_waf_block record per inmate detail fetch that was blocked (deduped per inmate and failure mode over 24 hours), and one detail_degraded record per sweep in which detail fetches failed systemically. Cumulative denied access sums each roster denial period from its first blocked cycle to its recovery; a period still open at build time accrues up to the build timestamp. The scorecard reads BLOCKED when either the roster list or the detail pages have an open denial period. These figures regenerate every build and are mirrored as JSON at transparency_metrics.json.

The Non-Evasion Policy

JCStream retrieves the roster from HCSO’s public inmate-search portal, using a mandatory delay between requests and a concurrency cap. A requester’s right to inspect and copy public records from the public office is governed by R.C. 149.43, which imposes duties on the public office or person responsible for public records. When the portal blocks that retrieval, JCStream does not attempt to circumvent the block: it rotates no IP addresses, uses no proxies, preserves the last-known-good roster, declines to publish a partial one, and documents the interruption. A clean, persisting, documented denial is itself part of the public record this site maintains.

Verify Independently

  1. Download the evidence ledger: waf_block_log.json. Every record carries prev_sha256, the SHA-256 of the previous record’s canonical JSON, forming an append-only hash chain.
  2. Clone the repository and run python -m scraper.verify_block_log data/waf_block_log.json. Exit code 0 means the chain is intact; any in-place edit or removed record breaks a link and the tool reports it.
  3. Cross-check published file integrity against SHA256SUMS and the repository’s authenticated git commit history.

Full schema documentation for the ledger and every other published file lives on the Data page.
